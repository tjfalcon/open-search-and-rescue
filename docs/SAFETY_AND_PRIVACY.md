# Safety and privacy baseline

Open Search and Rescue is coordination software. It is not an emergency service, dispatch system, or substitute for the agency of jurisdiction.

## Before an incident is published

1. Contact emergency services and the responsible public agency.
2. Establish a verified coordinator and a second approver.
3. Obtain consent or another documented lawful basis for personal information.
4. Publish the minimum information needed for the public action being requested.
5. Set an expiration time and a scheduled verification time.

## Defaults

- No precise operational location is public by default.
- No medical details, credentials, access tokens, internal team assignments, or minors' details belong on the public page.
- Volunteer guidance defaults to “do not self-deploy.”
- Public uploads are disabled until moderation, malware scanning, retention, and access controls are implemented.
- A resolved or expired incident stops recruiting volunteers immediately.

## Demonstration data

The hosted demonstration must use synthetic people, organizations, places, and events. Historical real-world incident data must not be republished as a current call to action. The previous prototype data was removed from the current application source on 2026-09-10; Git history remains available to the repository owner for audit and should be rewritten before broad production distribution if permanent erasure is required.

## Reporting a problem

Open a private security advisory in the GitHub repository for a vulnerability. Do not place personal incident data in a public issue.
